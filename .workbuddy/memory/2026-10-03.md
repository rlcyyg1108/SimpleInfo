## 修复用户 runClient 报出的 12 个编译错误

用户在 IDEA 里 `prepareRunClientCompile` 失败，12 个错误。根因是上一轮只做了**语法解析**，
没做符号解析 —— 大量 Forge API 名称/签名是凭记忆写的，没核实。全部已修：

1. **`ForgeConfigSpec.IntegerValue` 不存在**（8 处错误）—— 真名是 `IntValue`。
   `IntegerValue` / `LongValue` / `DoubleValue` / `BooleanValue` 才是 Forge 的内部类命名。
2. **`rebuildWidgets()` 可见性冲突** —— `Screen` 里它是 `protected`，我写成 `private`。
   但更深一层：**这个方法根本不该覆写**。查字节码确认调用链是
   `init(Minecraft,int,int)` → `init()`，而 `resize` → `repositionElements` → `rebuildWidgets` → `init()`。
   `rebuildWidgets` 是 Forge 内部的「清控件 + clearFocus + post ScreenEvent.Init.Pre/Post + 调 init()」包装器，
   覆写它会跳过整条事件链。已改为覆写 `protected void init()`。
3. **`FONT_SCALE.get()` 是装箱 `Double`**，`(float) Double` 在 Java 里非法（已实测确认）。
   改为经 `SimpleInfoConfig.fontScale()`（返回原始 `double`）中转。
4. **`ConfigScreenFactory` 走错构造器重载** —— 它是 record，有
   `Function<Screen,Screen>` 和 `BiFunction<Minecraft,Screen,Screen>` 两个构造器，
   我用了 BiFunction 但 `SimpleInfoConfigScreen` 只有一个参数。改用 `SimpleInfoConfigScreen::new`。
5. **`DistExecutor.safeRunWhenOn` 第二参是 `Supplier<SafeRunnable>`** —— 我传了方法引用，
   而方法引用不能直接当 lambda 体。最终写法是两层 lambda：
   `safeRunWhenOn(Dist.CLIENT, () -> () -> ClientHooks.registerConfigScreenFactory(context))`。
6. 顺带消掉 `ModLoadingContext.get()` 的 **deprecated-for-removal 警告** ——
   把 `FMLJavaModLoadingContext` 从主类构造器传进 `ClientHooks`，不在内部调 `get()`。

### 自检方式升级（重要）
本轮改用**裸 javac 完整类型检查**（不走 Gradle）：拼 classpath + 写 argfile，11 个文件秒级完成，
0 错误。比上一轮的语法解析强得多 —— 语法解析查不出「类名不存在」「签名不匹配」这类问题，
而这次 12 个错误里 12 个都是符号问题。方法与坑已写入 MEMORY.md。

argfile 的坑：**必须全用正斜杠**，`\` 被 javac 当转义符，路径会变成 `D:AAAmpminecraft...`。

## 修复 runClient 启动后的运行时错误：`Unsafe Referent usage found in safe referent method`

用户 `runClient` 已经能进游戏了（fmlloader 问题解决），但模组加载阶段崩了：

```
FATAL [net.minecraftforge.fml.DistExecutor]: Detected unsafe referent usage,
       please view the code at .../SimpleInfo.<init>(SimpleInfo.java:33)
java.lang.RuntimeException: Unsafe Referent usage found in safe referent method
  at DistExecutor.validateSafeReferent(DistExecutor.java:254)
  at DistExecutor.safeRunWhenOn(DistExecutor.java:121)
```

### 根因（javap 反汇编确认，不是猜的）
`DistExecutor.validateSafeReferent` 的实际逻辑：

```java
if (FMLEnvironment.production) return;            // 只在开发环境跑
SafeReferent obj = supplier.get();                 // 取内层那个 SafeRunnable
找 obj.getClass() 上有没有 writeReplace()（可序列化 lambda 才有）
SerializedLambda sl = (SerializedLambda) writeReplace.invoke(obj);
if (Objects.equals(sl.getCapturingClass(), sl.getImplClass()))   // ← 相等就炸
    throw new RuntimeException("Unsafe Referent usage found in safe referent method");
```

**内联 lambda 的方法体一定编译成"所在类"的合成方法 `lambda$new$0`**，
所以 `getCapturingClass() == getImplClass()` 恒成立 → 只要写内联 lambda 就必炸。
用 `safeRunWhenOn` 就必须把内层写成"指向另一个类的静态方法引用"（implClass != capturingClass），
但那样就拿不到 `context` 构造器参数了。

另外反汇编还确认：`runWhenOn` 直接委托给 `unsafeRunWhenOn`，
`unsafeRunWhenOn` = `if (FMLEnvironment.dist == dist) supplier.get().run();`
—— **两者运行逻辑完全一致**，`safe*` 只是多跑一次这条 dev 期校验。

### 修复
`SimpleInfo.java` 里 `safeRunWhenOn` → **`unsafeRunWhenOn`**，其余不动：

```java
DistExecutor.unsafeRunWhenOn(Dist.CLIENT,
        () -> () -> ClientHooks.registerConfigScreenFactory(context));
```

Dist 隔离依然成立：`ClientHooks` 只出现在内层 lambda 的字节码里，常量池按需解析，
Dist 不匹配时 `get()` 根本不会被调用，服务端不会加载它。

顺带把 `ClientHooks` 类注释里那句写错的示例（`safeRunWhenOn(... ClientHooks::registerConfigScreenFactory)`）改对了。

### 顺带修正的旧错误记录
MEMORY.md 里原来写着"用 `safeRunWhenOn` + 两层 lambda"——**这条是错的**（能编译、运行必炸），已改。

## 22:00 前后 — 元数据修复 + 配置界面第二轮改版

### 1. 模组名乱码（已定案，重要）
`gradle.properties` 里 `mod_name=简单信息展示`（**UTF-8**），但 Gradle 用 `java.util.Properties`
按 **ISO-8859-1** 读 `.properties` → 得到乱码串 M；`processResources` 的 `expand`
再以 **UTF-8** 把 M 写进 `mods.toml`。
**铁证**：`build/resources/main/META-INF/mods.toml` 里
`displayName` 的字节是 `C3 A7 C2 AE C2 80 ...` = 「UTF-8 编码的 Latin-1 乱码串」。
**修法**：`.properties` 里的非 ASCII 一律写 `\uXXXX` 转义（`Properties` 会解开）。
→ `mod_name=\u7B80\u5355\u4FE1\u606F\u5C55\u793A`。**关键推论**：expand 的输出字符集是 UTF-8
（否则 GBK 字节会让 mods.toml 变成非法 UTF-8，Forge 读时会抛 MalformedInputException），
所以写中文是安全的。

### 2. CycleButton 会凭空多一个冒号（重要坑）

### 新结论：原版字体自带 unifont，BMP 符号默认可渲染
1.20.1 字体链含 `minecraft:include/unifont`（`unihex` provider，`hex_file=minecraft:font/unifont.zip`，
覆盖整个 BMP），所以 `↺`(U+21BA) 之类符号**默认就能显示**，不必手绘图标。
查证方法：解析 `~/.gradle/caches/forge_gradle/assets/indexes/5.json` 的 `objects`，
按 hash 读 `~/.gradle/caches/forge_gradle/assets/objects/<前2位>/<hash>`。

## 给 MC 分配内存改为 4G
